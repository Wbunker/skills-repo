# Java Value Objects

## Approach Selection

| Use case | Approach |
|---|---|
| Java 16+, new code | Record with compact constructor |
| Pre-Java 16 or Lombok project | Lombok `@Value` |
| JPA single-column mapping with true immutability | `@AttributeConverter` |
| JPA multi-column mapping (less pure) | `@Embeddable` (requires non-final fields) |
| Complex equality (exclude some fields) | Manual `equals`/`hashCode` override |

---

## Pattern 1: Java Records (Java 16+, preferred)

```java
public record EmailAddress(String value) {
    // Compact constructor: runs before field assignments
    // Validate and normalize the parameter, not this.value
    public EmailAddress {
        Objects.requireNonNull(value, "email must not be null");
        value = value.strip().toLowerCase();
        if (!value.matches("^[^@]+@[^@]+\\.[^@]+$")) {
            throw new IllegalArgumentException("Invalid email: " + value);
        }
    }

    public String domain() {
        return value.substring(value.indexOf('@') + 1);
    }
}

// Records auto-generate: equals(), hashCode(), toString(), accessor value()
EmailAddress e1 = new EmailAddress("USER@EXAMPLE.COM");
EmailAddress e2 = new EmailAddress("user@example.com");
assert e1.equals(e2);  // true — structural equality
```

**Record rules:**
- Compact constructor body runs before the compiler inserts field assignments — assign to the parameter (not `this.field`)
- Implicitly `final` — cannot be extended
- All components are `private final` — no setters
- Auto-generates `equals()`, `hashCode()`, `toString()` based on all components
- Accessor name matches component name: `email.value()`, not `email.getValue()`

### Multi-component record

```java
public record Money(BigDecimal amount, Currency currency) {
    public Money {
        Objects.requireNonNull(amount, "amount required");
        Objects.requireNonNull(currency, "currency required");
        if (amount.compareTo(BigDecimal.ZERO) < 0) {
            throw new IllegalArgumentException("amount must be non-negative");
        }
        amount = amount.setScale(2, RoundingMode.HALF_UP);
    }

    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalStateException("Currency mismatch");
        }
        return new Money(this.amount.add(other.amount), this.currency);
    }
}
```

## Pattern 2: Lombok `@Value`

```java
@Value  // all fields private final, no setters, generates equals/hashCode/toString/getters, class is final
public class Money {
    BigDecimal amount;
    Currency currency;

    // Private constructor generated by @Value; expose via static factory
    public static Money of(BigDecimal amount, Currency currency) {
        if (amount.compareTo(BigDecimal.ZERO) < 0) {
            throw new IllegalArgumentException("amount must be non-negative");
        }
        return new Money(amount.setScale(2, RoundingMode.HALF_UP), currency);
    }

    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalStateException("Currency mismatch");
        }
        return Money.of(this.amount.add(other.amount), this.currency);
    }
}
```

Add `@Value(staticConstructor = "of")` to make the constructor private and expose `Money.of(...)` automatically.

## JPA Mapping: `@AttributeConverter` (preferred — allows final fields)

Use for single-column VOs where true immutability matters.

```java
// The VO — truly immutable, final field
public record EmailAddress(String value) {
    public EmailAddress {
        value = Objects.requireNonNull(value).strip().toLowerCase();
        if (!value.contains("@")) throw new IllegalArgumentException("Invalid email");
    }
}

// Converter — maps VO ↔ DB column
@Converter(autoApply = true)
public class EmailAddressConverter implements AttributeConverter<EmailAddress, String> {
    @Override
    public String convertToDatabaseColumn(EmailAddress address) {
        return address == null ? null : address.value();
    }

    @Override
    public EmailAddress convertToEntityAttribute(String dbData) {
        return dbData == null ? null : new EmailAddress(dbData);
    }
}

// Entity — no change needed when autoApply = true
@Entity
public class User {
    @Id private Long id;
    private EmailAddress email;  // converter applied automatically
}
```

## JPA Mapping: `@Embeddable` (multi-column, less pure)

Requires: non-final fields, protected no-arg constructor (Hibernate needs it).

```java
@Embeddable
public class PersonName {
    private String firstName;
    private String lastName;

    protected PersonName() {}  // Hibernate only — never call from domain code

    public PersonName(String firstName, String lastName) {
        this.firstName = Objects.requireNonNull(firstName, "firstName required").strip();
        this.lastName  = Objects.requireNonNull(lastName, "lastName required").strip();
    }

    // Getters (no setters)
    public String firstName() { return firstName; }
    public String lastName()  { return lastName; }

    @Override
    public boolean equals(Object o) {
        if (!(o instanceof PersonName pn)) return false;
        return firstName.equals(pn.firstName) && lastName.equals(pn.lastName);
    }

    @Override
    public int hashCode() {
        return Objects.hash(firstName, lastName);
    }
}

// Entity usage
@Entity
public class Employee {
    @Id private Long id;
    @Embedded
    @AttributeOverrides({
        @AttributeOverride(name = "firstName", column = @Column(name = "first_name")),
        @AttributeOverride(name = "lastName",  column = @Column(name = "last_name"))
    })
    private PersonName name;
}
```

**`@Embeddable` gotcha:** If all columns are NULL in the DB, Hibernate returns `null` for the whole embedded object (not a VO with null fields). Use `@Embeddable` + Hibernate's `@Parent` annotation or check for null when loading.

## Bean Validation on Records

```java
public record User(
    @NotBlank @Size(min = 2, max = 50) String name,
    @Email @NotBlank String email,
    @Min(18) @Max(120) int age
) {
    // Triggers JSR-380 validation via factory (not automatic in compact constructor)
    public static User createValidated(String name, String email, int age) {
        User user = new User(name, email, age);
        try (var factory = Validation.buildDefaultValidatorFactory()) {
            Set<ConstraintViolation<User>> violations = factory.getValidator().validate(user);
            if (!violations.isEmpty()) throw new ConstraintViolationException(violations);
        }
        return user;
    }
}
```

## Common Gotchas

| Gotcha | Fix |
|---|---|
| Compact constructor: assigning `this.field` | Assign to the parameter (`value = ...`), not `this.value` — compiler adds assignments after |
| Record + Hibernate `@Embeddable` | Hibernate 6+ supports records as `@Embeddable` but they cannot hold `@OneToMany`/`@ManyToMany` |
| `@Embeddable` requires no-arg constructor | Add `protected NoArgConstructor(){}` but never expose it to domain code |
| All-null embeddable columns → null object | Handle null in entity getter or use Hibernate `@NotFound` |
| Records cannot extend other classes | Use interface extraction or composition for shared VO behavior |
| `BigDecimal` equality pitfall | `new BigDecimal("1.0").equals(new BigDecimal("1.00"))` is `false` — use `compareTo()` for money comparisons |
