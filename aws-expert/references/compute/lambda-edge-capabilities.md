# Lambda@Edge — Capabilities Reference

For CLI commands, see [lambda-edge-cli.md](lambda-edge-cli.md).
For base Lambda capabilities, see [lambda-capabilities.md](lambda-capabilities.md).
For CloudFront integration context, see [../networking/cloudfront-capabilities.md](../networking/cloudfront-capabilities.md).

---

## What Lambda@Edge Is

Lambda@Edge is an extension of AWS Lambda that runs Node.js or Python functions at AWS locations close to viewers — at CloudFront's regional edge cache PoPs (~13 locations globally). Functions execute in response to CloudFront events without provisioning servers. Use Lambda@Edge for logic that requires full Lambda capabilities (network calls, large compute, auth); use [CloudFront Functions](../networking/cloudfront-capabilities.md) for sub-millisecond simple transforms.

**Not supported with gRPC requests.**

---

## The 4 Trigger Events

```
Viewer → [viewer-request] → CloudFront cache check
           cache hit ──────────────────────────────────→ [viewer-response] → Viewer
           cache miss → [origin-request] → Origin → [origin-response] ──────↗
```

### Viewer Request
Fires when CloudFront receives a request from a viewer, **before** the cache check.
- Runs on every request (cache hit or miss)
- Can generate a synthetic response (short-circuit to viewer)
- **Does NOT fire** for custom error pages or automatic HTTP→HTTPS redirects

### Origin Request
Fires only when CloudFront forwards a request to the origin (**cache miss only**).
- Does not run when served from cache
- Can modify origin, URI, headers, query string, or generate a synthetic response
- CloudFront-added headers (e.g., `CloudFront-Viewer-Country`) **are available** here
- CloudFront performs DNS resolution on the origin domain **before** invoking the function; if DNS fails, function is skipped and CloudFront returns 502

### Origin Response
Fires after CloudFront receives the origin response, **before** caching.
- Runs even if the origin returns an error
- Can modify response headers and body
- **Does NOT fire** if the response is served from cache (cache hit) or was generated by an origin-request function

### Viewer Response
Fires before returning the response to the viewer (runs even on cache hits).
- Can modify response headers
- **Cannot modify the HTTP status code** (restriction applies to viewer-response only)
- **Does NOT fire** when the origin returns 400+, for custom error pages, for responses generated by a viewer-request function, or for automatic HTTP→HTTPS redirects

### Trigger Comparison

| | viewer-request | origin-request | origin-response | viewer-response |
|---|---|---|---|---|
| **Runs on cache hits** | Yes | No | No | Yes |
| **Can modify request** | Yes | Yes | N/A | N/A |
| **Can modify response** | N/A | N/A | Yes | Yes |
| **Can generate synthetic response** | Yes | Yes | No | No |
| **Can modify status code** | Yes (synthetic) | Yes (synthetic) | Yes | **No** |
| **CloudFront geo/device headers** | No | Yes | Yes | Yes |
| **Fires on origin errors** | N/A | N/A | Yes | No |

## Limits and Quotas

### Per-Event-Type Limits

| Quota | Viewer Request/Response | Origin Request/Response |
|---|---|---|
| **Generated/modified response size** (headers + body) | 40 KB | 1 MB |
| **Request body exposed** (Include Body option) | Truncated at 40 KB | Truncated at 1 MB |
| **Replaced body (plain text)** | 40 KB | 1 MB |
| **Replaced body (base64-encoded)** | 53.2 KB | 1.33 MB |

### General Lambda@Edge Limits

| Quota | Value |
|---|---|
| **Function timeout** | 30 seconds |
| **Memory** | Up to 10,240 MB (same as Lambda) |
| **Max compressed deployment package** | 50 MB |
| **Max ephemeral storage** | 512 MB (less than standard Lambda's 10 GB) |
| **Concurrent executions** | 1,000 per AWS Region (shared with Lambda) |
| **Lambda@Edge functions per distribution** | 100 |
| **Distributions per account with L@E** | 500 |
| **Distributions associated with same function** | 500 |
| **Requests per second per region** | 10,000 |

## Deployment Requirements

### Region Constraint
Functions **must be created in `us-east-1` (US East N. Virginia)**. When you add a CloudFront trigger, AWS automatically replicates the function to edge locations globally.

### Versioning Requirement
You **must reference a numbered version ARN** — `$LATEST` and aliases are **not allowed**.

```
arn:aws:lambda:us-east-1:123456789012:function:MyEdgeFunction:3
```

### Replication
- Service-linked role `AWSServiceRoleForLambdaReplicator` handles replication automatically when you add a trigger
- Replication lag: propagation to edge locations can take a few minutes after association
- To delete a Lambda@Edge function, you must first remove all CloudFront triggers and wait for replicas to be deleted

### Association to Cache Behaviors
Each CloudFront cache behavior can have up to 4 Lambda@Edge associations (one per event type). You associate via the CloudFront distribution configuration or the Lambda console trigger UI.

### Account Constraint
The Lambda function and the CloudFront distribution must be owned by the **same AWS account**.

### Not Supported With
- gRPC CloudFront distributions
- Microsoft Smooth Streaming distributions

### Combining CloudFront Functions and Lambda@Edge
You **cannot** have both a CloudFront Function and a Lambda@Edge function on the **same** event type (e.g., both on viewer-request). You **can** combine them on different event types — for example, a CloudFront Function on viewer-request and a Lambda@Edge function on origin-request in the same cache behavior.

## IAM Requirements

### Execution Role Trust Policy
The role must allow **both** Lambda service principals to assume it:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": [
          "lambda.amazonaws.com",
          "edgelambda.amazonaws.com"
        ]
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

Attach `AWSLambdaBasicExecutionRole` to allow CloudWatch Logs writes. Add additional policies for any AWS resources the function accesses (S3, DynamoDB, etc.).

### Permissions Required to Associate L@E Functions

| Permission | Purpose |
|---|---|
| `lambda:GetFunction` | Get function config and presigned S3 URL |
| `lambda:EnableReplication*` | Allow replication service to read function |
| `lambda:DisableReplication*` | Allow replication service to delete function |
| `iam:CreateServiceLinkedRole` | Create AWSServiceRoleForLambdaReplicator (first time only) |
| `cloudfront:UpdateDistribution` | Associate function with distribution |

### Service-Linked Roles (Auto-Created)
- **AWSServiceRoleForLambdaReplicator**: created on first trigger; replicates functions to regions
- **AWSServiceRoleForCloudFrontLogger**: created when a distribution has L@E association; pushes error logs to CloudWatch

## Unsupported Lambda Features

The following standard Lambda features are **not available** in Lambda@Edge functions:

| Feature | Notes |
|---|---|
| Lambda Layers | Not supported |
| Environment variables | Not supported (reserved vars like `AWS_REGION` are auto-populated) |
| VPC access | Not supported; functions cannot connect to VPC resources |
| Dead Letter Queues | Not supported |
| X-Ray tracing (`aws-xray-sdk`) | Not supported |
| Provisioned concurrency | Not supported |
| Container image deployment | Not supported; zip deployment only |
| arm64 architecture | Not supported; x86_64 only |
| Ephemeral storage > 512 MB | Max is 512 MB (standard Lambda supports up to 10 GB) |
| Runtime management controls | Only **Auto** mode is supported |
| Customer managed key for .zip packages | Not supported |

## Supported Runtimes

Latest versions of **Node.js** and **Python** only. Check the [Lambda supported runtimes page](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtimes.html#runtimes-supported) for current versions. Using deprecated runtimes: existing associations continue running, but new functions or updates with deprecated runtimes are blocked.

**Node.js 18+ note**: The Lambda console creates `index.mjs` by default; rename to `index.js` if using CommonJS `exports.handler` syntax.

## Logging

Lambda@Edge writes CloudWatch Logs to the **AWS Region closest to the viewer** that processed the request (not necessarily us-east-1).

- Log group name: `/aws/lambda/us-east-1.<function-name>` (includes `us-east-1.` prefix even in other regions)
- You must check CloudWatch in **multiple regions** to find logs for globally distributed traffic
- The `AWSServiceRoleForCloudFrontLogger` service-linked role is required and auto-created

## Event JSON Structure

### Request Events (viewer-request and origin-request)

```json
{
  "Records": [{
    "cf": {
      "config": {
        "distributionDomainName": "d111111abcdef8.cloudfront.net",
        "distributionId": "EDFDVBD6EXAMPLE",
        "eventType": "viewer-request",
        "requestId": "4TyzHTaYWb1GX1qTfsHhEqV6HUDd_BzoBZnwfnvQc_1oF26ClkoUSEQ=="
      },
      "request": {
        "clientIp": "203.0.113.178",
        "method": "GET",
        "uri": "/images/photo.jpg",
        "querystring": "size=large&format=webp",
        "headers": {
          "host": [{ "key": "Host", "value": "d111111abcdef8.cloudfront.net" }],
          "user-agent": [{ "key": "User-Agent", "value": "curl/7.66.0" }],
          "cookie": [{ "key": "Cookie", "value": "session=abc123; variant=B" }]
        },
        "origin": {
          "custom": {
            "domainName": "example.org",
            "port": 443,
            "protocol": "https",
            "path": "",
            "keepaliveTimeout": 5,
            "readTimeout": 30,
            "responseCompletionTimeout": 30,
            "sslProtocols": ["TLSv1.2"],
            "customHeaders": {}
          }
        }
      }
    }
  }]
}
```

**Notes on `origin` field (origin-request only):**
- `origin` is present only in origin-request events (not viewer-request)
- Can be either `custom` (shown above) or `s3` (see S3 origin fields below)
- Modifying `origin` fields dynamically routes the request to a different origin
- Can switch between custom and S3 origin objects

**S3 origin object:**
```json
"s3": {
  "domainName": "my-bucket.s3.us-east-1.amazonaws.com",
  "region": "us-east-1",
  "authMethod": "none",
  "path": "",
  "customHeaders": {}
}
```

### Response Events (origin-response and viewer-response)

Response events include both `request` (read-only) and `response` (read/write) objects:

```json
{
  "Records": [{
    "cf": {
      "config": {
        "distributionDomainName": "d111111abcdef8.cloudfront.net",
        "distributionId": "EDFDVBD6EXAMPLE",
        "eventType": "origin-response",
        "requestId": "4TyzHTaYWb1GX1qTfsHhEqV6HUDd_BzoBZnwfnvQc_1oF26ClkoUSEQ=="
      },
      "request": { "...": "same as request event, read-only in response triggers" },
      "response": {
        "status": "200",
        "statusDescription": "OK",
        "headers": {
          "content-type": [{ "key": "Content-Type", "value": "text/html; charset=utf-8" }],
          "cache-control": [{ "key": "Cache-Control", "value": "max-age=3600" }],
          "x-custom-header": [{ "key": "X-Custom-Header", "value": "my-value" }]
        }
      }
    }
  }]
}
```

### Request Field Access Per Trigger

| Field | viewer-request | origin-request | origin-response | viewer-response |
|---|---|---|---|---|
| `clientIp` | read-only | read-only | read-only | read-only |
| `headers` | read/write | read/write | read/write | read/write |
| `method` | read-only | read-only | read-only | read-only |
| `querystring` | read/write | read/write | read-only | read-only |
| `uri` | read/write | read/write | read-only | read-only |
| `body` | read/write (Include Body) | read/write (Include Body) | not exposed | not exposed |
| `origin` | not present | read/write | read-only | not present |
| `response.status` | n/a | n/a | read/write | **read-only** |
| `response.headers` | n/a | n/a | read/write | read/write |

### Headers Format
Headers object keys are **always lowercase**. Each header is an **array** of `{key, value}` objects (supports multi-value headers). The `key` field preserves original casing; `value` is the header value.

```javascript
// Read a header
const ua = request.headers['user-agent']?.[0]?.value;

// Add/modify a header
request.headers['x-forwarded-for'] = [{ key: 'X-Forwarded-For', value: '1.2.3.4' }];

// Read cookies (not parsed — split manually)
const cookies = request.headers.cookie?.[0]?.value.split('; ') ?? [];
```

## Request Body Access (Include Body Option)

Not enabled by default. To expose the request body:
- Console: check **Include Body** in the Lambda Function Association
- API/CloudFormation: set `IncludeBody: true` in `LambdaFunctionAssociation`
- Only available for writable HTTP methods (POST, PUT, DELETE, etc.)

Body is always **base64-encoded** when exposed to the function:

```javascript
// Read body
const body = Buffer.from(request.body.data, 'base64').toString();

// Replace body
request.body.action = 'replace';
request.body.encoding = 'text';  // 'text' or 'base64'
request.body.data = 'new body content';
```

If you read body as read-only (don't set `action: 'replace'`), CloudFront sends the full original body to the origin even if it was truncated in the event.

## Generating Synthetic Responses

In **viewer-request** and **origin-request** triggers, return a response object instead of the request object to short-circuit the request (no origin call):

```javascript
// Node.js — return a synthetic response from a request trigger
exports.handler = (event, context, callback) => {
    const response = {
        status: '200',          // string, not integer
        statusDescription: 'OK',
        headers: {
            'content-type': [{ key: 'Content-Type', value: 'text/html' }],
            'cache-control': [{ key: 'Cache-Control', value: 'max-age=100' }]
        },
        body: '<html><body>Hello from the edge!</body></html>'
    };
    callback(null, response);
};
```

## Key Code Patterns

### URL Rewrite (origin-request)
```javascript
'use strict';
exports.handler = (event, context, callback) => {
    const request = event.Records[0].cf.request;
    // Rewrite /old-path/ → /new-path/
    request.uri = request.uri.replace(/^\/old-path\//, '/new-path/');
    callback(null, request);
};
```

### HTTP → HTTPS Redirect (viewer-request)
```javascript
'use strict';
exports.handler = (event, context, callback) => {
    const request = event.Records[0].cf.request;
    const headers = request.headers;
    if (headers['cloudfront-forwarded-proto']?.[0]?.value === 'http') {
        const response = {
            status: '301',
            statusDescription: 'Moved Permanently',
            headers: {
                location: [{ key: 'Location', value: `https://${headers.host[0].value}${request.uri}` }]
            }
        };
        return callback(null, response);
    }
    callback(null, request);
};
```

### A/B Testing via Cookie (origin-request)
```javascript
'use strict';
exports.handler = (event, context, callback) => {
    const request = event.Records[0].cf.request;
    const headers = request.headers;
    // Check variant cookie
    let variant = 'control';
    if (headers.cookie) {
        for (const c of headers.cookie) {
            const match = c.value.match(/variant=([^;]+)/);
            if (match) { variant = match[1]; break; }
        }
    }
    // Route to different origins
    if (variant === 'treatment') {
        request.origin.custom.domainName = 'treatment.example.com';
        request.headers['host'] = [{ key: 'Host', value: 'treatment.example.com' }];
    }
    callback(null, request);
};
```

### Add Security Headers (origin-response)
```javascript
'use strict';
exports.handler = (event, context, callback) => {
    const response = event.Records[0].cf.response;
    const h = response.headers;
    h['strict-transport-security'] = [{ key: 'Strict-Transport-Security', value: 'max-age=63072000; includeSubdomains; preload' }];
    h['x-content-type-options'] = [{ key: 'X-Content-Type-Options', value: 'nosniff' }];
    h['x-frame-options'] = [{ key: 'X-Frame-Options', value: 'DENY' }];
    h['x-xss-protection'] = [{ key: 'X-XSS-Protection', value: '1; mode=block' }];
    h['referrer-policy'] = [{ key: 'Referrer-Policy', value: 'same-origin' }];
    callback(null, response);
};
```

### Normalize Query String for Better Cache Hit Ratio (origin-request)
```javascript
'use strict';
const querystring = require('querystring');
exports.handler = (event, context, callback) => {
    const request = event.Records[0].cf.request;
    const params = querystring.parse(request.querystring.toLowerCase());
    const sortedParams = {};
    Object.keys(params).sort().forEach(key => { sortedParams[key] = params[key]; });
    request.querystring = querystring.stringify(sortedParams);
    callback(null, request);
};
```

### Redirect Unauthenticated Users (viewer-request)
```javascript
'use strict';
exports.handler = (event, context, callback) => {
    const request = event.Records[0].cf.request;
    const headers = request.headers;
    const cookies = {};
    if (headers.cookie) {
        headers.cookie[0].value.split(';').forEach(c => {
            const [k, v] = c.trim().split('=');
            cookies[k] = v;
        });
    }
    if (cookies['session-id']) { return callback(null, request); }
    const redirectUrl = encodeURIComponent(`https://${headers.host[0].value}${request.uri}`);
    callback(null, {
        status: '302',
        statusDescription: 'Found',
        headers: { location: [{ key: 'Location', value: `https://auth.example.com/login?redirect=${redirectUrl}` }] }
    });
};
```

### Dynamic Origin Selection by Geolocation (origin-request)
```javascript
'use strict';
exports.handler = (event, context, callback) => {
    const request = event.Records[0].cf.request;
    const country = request.headers['cloudfront-viewer-country']?.[0]?.value ?? 'US';
    // CloudFront-Viewer-Country header requires origin request policy to forward it
    const originMap = {
        'EU': 'eu-origin.example.com',
        'AP': 'apac-origin.example.com',
    };
    const prefix = country.startsWith('EU') || ['DE','FR','GB'].includes(country) ? 'EU' :
                   ['JP','AU','SG'].includes(country) ? 'AP' : null;
    if (prefix) {
        request.origin.custom.domainName = originMap[prefix];
        request.headers['host'] = [{ key: 'Host', value: originMap[prefix] }];
    }
    callback(null, request);
};
```

## Lambda@Edge vs CloudFront Functions

| Feature | Lambda@Edge | CloudFront Functions |
|---|---|---|
| **Runtime** | Node.js, Python | JavaScript (ECMAScript 5.1+) |
| **Trigger points** | All 4 (viewer req/res, origin req/res) | Viewer request/response only |
| **Execution locations** | ~13 regional edge PoPs | 400+ edge locations |
| **Max timeout** | 30 seconds | 1 ms |
| **Memory** | Up to 10,240 MB | 2 MB |
| **Package size** | 50 MB (compressed) | 10 KB |
| **Network calls** | Yes | No |
| **Request body access** | Yes (with Include Body) | No |
| **KV store access** | No | Yes (CloudFront KeyValueStore) |
| **Pricing** | Per-request + GB-second | Per-request (cheaper) |
| **Use case** | Auth, complex logic, origin routing, API calls, response generation | URL rewrites, header manipulation, simple redirects, cache-key normalization |

**Rule of thumb**: Use CloudFront Functions for pure header/URL transforms at viewer events. Use Lambda@Edge when you need network calls, large computation, body access, or origin-event triggers.

---

## Pricing

Lambda@Edge is priced per-request and per GB-second of compute duration, billed in each AWS Region where functions execute. No charge when functions are idle. More expensive than CloudFront Functions for equivalent viewer-event work; cheaper than running compute on origin servers for work that can be done at the edge.

## Key Gotchas

- **Viewer-response cannot change status code** — CloudFront enforces this; only origin-response and synthetic responses (viewer-request/origin-request) can set status codes.
- **CloudFront-added headers not in viewer-request** — `CloudFront-Viewer-Country`, `CloudFront-Is-Mobile-Viewer`, etc. are added by CloudFront *after* viewer-request, so they're only accessible in origin-request and beyond. Must be forwarded via origin request policy.
- **Logs scatter across regions** — logs go to the region nearest the viewer, not to us-east-1. You must search CloudWatch in multiple regions.
- **Replication lag** — after updating a function, new associations take minutes to propagate globally.
- **No $LATEST** — always publish a new version and reference the versioned ARN in CloudFront.
- **Function execution blocks the request** — Lambda@Edge functions are synchronous; every ms of execution adds latency for viewers. Keep functions fast.
- **Viewer-response doesn't fire on 400+ from origin** — if the origin returns an error, viewer-response is skipped. Use origin-response to handle error bodies.
- **Body truncation is silent** — `request.body.inputTruncated` is `true` if truncated; always check before processing large bodies.
- **DNS pre-resolution for origin-request** — CloudFront resolves the origin hostname before invoking the function. DNS failures bypass the function entirely.
- **No gRPC** — Lambda@Edge cannot be used with CloudFront gRPC distributions.
- **No environment variables — use module-level caching for secrets** — Fetch from Parameter Store or Secrets Manager at cold-start time and cache in module scope. The cached value persists across warm invocations for the life of the execution environment:

```javascript
let cachedSecret = null;
const { SSMClient, GetParameterCommand } = require('@aws-sdk/client-ssm');
const ssm = new SSMClient({ region: 'us-east-1' });

exports.handler = async (event) => {
    if (!cachedSecret) {
        const result = await ssm.send(new GetParameterCommand({
            Name: '/myapp/origin-secret',
            WithDecryption: true
        }));
        cachedSecret = result.Parameter.Value;
    }
    const request = event.Records[0].cf.request;
    request.headers['x-origin-verify'] = [{ key: 'X-Origin-Verify', value: cachedSecret }];
    return request;
};
```

- **Per-cache-behavior scope** — Lambda@Edge associations are per cache behavior, not per distribution. The default cache behavior (`*`) does not automatically cover other behaviors.
- **viewer-response fires on cache hits** — unlike origin-response (cache misses only), viewer-response runs on every request including cache hits. A heavy viewer-response function executes at full traffic volume with no caching benefit.
- **Cannot combine CloudFront Functions + Lambda@Edge on the same event type** — you can pair CF Functions on viewer-request with Lambda@Edge on origin-request, but not two functions on the same event.
