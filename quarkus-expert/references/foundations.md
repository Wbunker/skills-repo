## Why Quarkus?

Traditional Java frameworks (Spring Boot, Java EE) were designed for long-running, monolithic servers where a slow 30–60 second startup is acceptable. The cloud-native era demands:

- **Fast startup** — Lambda/Knative charges per 100ms; a 50ms start beats a 10s start by 200×
- **Low memory footprint** — containers are billed by RAM; 50 MB RSS vs. 500 MB matters at scale
- **Kubernetes-native** — health probes, configuration injection, graceful shutdown built in, not bolted on

Quarkus solves this by moving framework work **from runtime to build time**. ClassPath scanning, reflection setup, CDI proxy generation, configuration parsing — all happen during `mvn package`, not during `java -jar`.

### Quarkus vs. Competitors

| | Quarkus | Spring Boot | Micronaut | Helidon |
|---|---|---|---|---|
| Build-time CDI | Yes | No | Yes | Partial |
| GraalVM native | First-class | Experimental | First-class | First-class |
| Dev Services | Yes | No | No | No |
| Standards (CDI, JAX-RS) | Yes | Partial | No | Yes |
| Ecosystem (extensions) | 500+ | Largest | Moderate | Small |

## Core Concepts

### Build-Time Augmentation

```
Source code
    │
    ▼
mvn package  ──► Augmentation phase (ClassInfo scanning, CDI wiring,
    │              config metadata, proxy generation)
    ▼
Generated bytecode + serialized metadata
    │
    ▼
JVM start: load pre-built state — no scanning, no reflection bootstrap
    │
    OR
    ▼
GraalVM native-image: AOT compile everything into a single binary
```

### Extension System

Every Quarkus feature is an **extension** — a Maven artifact with two parts:
- **Deployment JAR** — build-time augmentation logic (`@BuildStep` processors)
- **Runtime JAR** — what actually ships in the final app

Extensions are the unit of integration: each adds its own CDI beans, configuration schema, Dev Services, and health checks.

## Project Generation

### Via code.quarkus.io (web UI)
1. Pick group/artifact ID, Java version, build tool
2. Search and select extensions
3. Download ZIP, unpack, open in IDE

### Via Maven plugin
```bash
mvn io.quarkus.platform:quarkus-maven-plugin:3.x.x:create \
  -DprojectGroupId=com.example \
  -DprojectArtifactId=my-app \
  -Dextensions="resteasy-reactive,hibernate-orm-panache,jdbc-postgresql"
```

### Via Quarkus CLI
```bash
# Install CLI
sdk install quarkus

# Create project
quarkus create app com.example:my-app \
  --extensions="resteasy-reactive,hibernate-orm-panache"

# Add extensions later
quarkus ext add smallrye-health micrometer-registry-prometheus
```

### Generated Project Layout

```
my-app/
├── pom.xml                        # BOM import: quarkus-bom
├── src/
│   ├── main/
│   │   ├── java/com/example/      # Application source
│   │   ├── resources/
│   │   │   ├── application.properties
│   │   │   └── META-INF/resources/ # Static web content
│   │   └── docker/
│   │       ├── Dockerfile.jvm
│   │       └── Dockerfile.native
│   └── test/
│       └── java/com/example/
└── .mvn/wrapper/
```

### pom.xml Key Elements

```xml
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>io.quarkus.platform</groupId>
      <artifactId>quarkus-bom</artifactId>
      <version>${quarkus.platform.version}</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<build>
  <plugins>
    <plugin>
      <groupId>io.quarkus.platform</groupId>
      <artifactId>quarkus-maven-plugin</artifactId>
      <extensions>true</extensions>
    </plugin>
  </plugins>
</build>
```

## Running the Application

### JVM mode
```bash
./mvnw quarkus:dev          # Dev mode (live coding)
./mvnw package              # Build runnable JAR
java -jar target/quarkus-app/quarkus-run.jar
```

### Native mode

**Prerequisites:** GraalVM CE or Mandrel with `native-image` on PATH, or Docker for container-build.

```bash
# Native binary (requires GraalVM locally)
./mvnw package -Pnative

# Native binary built inside Docker (no local GraalVM needed)
./mvnw package -Pnative -Dquarkus.native.container-build=true

# Run
./target/my-app-1.0-runner
```

### Native build options

```properties
# application.properties
quarkus.native.container-build=true          # Use Docker to build
quarkus.native.builder-image=quay.io/quarkus/ubi-quarkus-mandrel-builder-image:22.3
quarkus.native.additional-build-args=-H:ReflectionConfigurationFiles=reflect-config.json
quarkus.native.resources.includes=**/*.json  # Include resource files
```

## Performance Characteristics

| Metric | JVM mode | Native mode |
|---|---|---|
| Start time (simple app) | ~1–2 s | ~20–50 ms |
| First-request latency | High (JIT warmup) | Low (AOT) |
| Peak throughput | High (JIT optimized) | Slightly lower |
| RSS at idle | ~200–400 MB | ~30–80 MB |
| Build time | Seconds | 2–5 minutes |
| Debugging | Full IDE support | Limited |

**Rule of thumb:** native for short-lived/serverless; JVM for long-running, throughput-sensitive services.

## Container Images

```bash
# Build JVM image (requires quarkus-container-image-docker or -jib)
./mvnw package -Dquarkus.container-image.build=true

# Build native image in container
./mvnw package -Pnative \
  -Dquarkus.native.container-build=true \
  -Dquarkus.container-image.build=true
```

```properties
quarkus.container-image.group=myorg
quarkus.container-image.name=my-app
quarkus.container-image.tag=1.0.0
quarkus.container-image.push=true
quarkus.container-image.registry=quay.io
```

## Extension Management

```bash
# List all available extensions
quarkus ext list

# Search for extensions
quarkus ext list --search=database

# Add extension
quarkus ext add hibernate-orm-panache

# Remove extension
quarkus ext remove hibernate-orm-panache

# List installed extensions
quarkus ext list --installed
```
